# Implementation Plan: Compress Images (client-side, privacy-first)

Catatan mode komunikasi: caveman ultra tetap aktif, tapi plan ini ditulis normal agar tidak ada ambiguitas teknis.

## Overview

Web app kompresi gambar 100% client-side di `web/compress-images/` dalam monorepo `everyday-tools`. Semua proses (decode, encode, download) jalan di browser — tidak ada byte gambar yang keluar device. Stack: TypeScript + Vite, vanilla (tanpa framework), Web Worker untuk encode, Vitest untuk unit test. Fase akhir upgrade encoder ke jSquash (MozJPEG/OxiPNG) di belakang interface yang sama.

Interpretasi "notasi jsoc" = **JSDoc** (standar dokumentasi JS/TS, tampil di IntelliSense). Plan ditulis dengan asumsi ini.

## Architecture Decisions

1. **Vanilla TS, tanpa framework (KISS).** UI-nya satu halaman sederhana: drop file, slider kualitas, tombol download. React/Vue menambah kompleksitas tanpa manfaat.
2. **Logika murni dipisah dari DOM (SRP + testability).** Semua fungsi non-UI murni (format ukuran, hitung statistik, validasi opsi, protokol worker) hidup di `src/core/` — diuji di Node tanpa browser nyata. Ini kunci agar TDD mungkin: `happy-dom`/`jsdom` tidak punya canvas encoder sungguhan, jadi bagian yang menyentuh canvas diisolasi di balik interface.
3. **Interface `ImageEncoder` (DIP/DRY).** Kontrak tunggal `encode(imageData: ImageData, options: EncodeOptions): Promise<Blob>`. Implementasi: `CanvasEncoder` (MVP) dan nanti `MozJpegEncoder`/`OxiPngEncoder` (jSquash). Worker dan UI tidak tahu encoder mana yang dipakai — penambahan codec tidak menyentuh kode lain.
4. **Web Worker sejak awal.** `new Worker(new URL('./worker.ts', import.meta.url), { type: 'module' })` (pola resmi Vite). UI tidak pernah freeze saat batch encode.
5. **Privasi terverifikasi, bukan sekadar klaim.** Nol dependency runtime di MVP. Setelah build, hasil `dist/` murni statis — dijalankan via `npx serve dist` atau GitHub Pages, nol network call saat pakai. Disataukan di README + dicek manual.
6. **Pengujian: TDD (red–green–refactor).** Setiap task dimulai dari test gagal, lalu implementasi minimal, lalu refactor. Fungsi canvas-dependent diuji lewat fake/injectable, bukan mock canvas tambal-sulam.
7. **Dokumentasi kode: JSDoc** di semua fungsi/_interface_ yang di-`export`: deskripsi, `@param`, `@returns`, `@throws` bila relevan.

### Phase 2: Core logic (TDD, tanpa DOM)

- [ ] **Task 3: core/format.ts — fungsi tampilan murni**
  `formatBytes(bytes: number): string` (B/KB/MB, 1 desimal), `savingsPercent(before, after): number`, `buildOutputFilename(name, ext): string` (`foto.png` + `webp` jadi `foto.webp`; hindari tabrakan `foto.min.png`). Mulai dari test gagal untuk tiap kasus tepi (0 byte, <1 KB, ratusan MB, nama tanpa ekstensi).
  **Acceptance:** semua test edge case lulus; JSDoc lengkap.
  **Dependencies:** Task 2. **Files:** src/core/format.ts, tests/format.test.ts. **Scope: S**

- [ ] **Task 4: core/types.ts + encoders/imageEncoder.ts — kontrak**
  Definisikan `EncodeOptions` (quality 0–100, format target), `EncodeRequest`/`EncodeResponse` (protokol worker, termasuk varian error), `CompressionResult`. `clampQuality(n): number` (0–100 → 0–1, clamp) diuji test-first.
  **Acceptance:** test clamp lulus; tipe dikonsumsi worker/UI tanpa `any`.
  **Dependencies:** Task 2. **Files:** src/core/types.ts, src/encoders/imageEncoder.ts, tests/types.test.ts. **Scope: S**

- [ ] **Task 5: encoders/canvasEncoder.ts — encoder MVP**
  `CanvasEncoder implements ImageEncoder`: decode `Blob` via `createImageBitmap`, resize opsional, gambar ke `OffscreenCanvas`, `convertToBlob({ type, quality })`. Konstruktor menerima dependensi yang bisa di-inject (`decode` + `toBlob`-like) sehingga logika orkestrasi diuji dengan fake di Node; jalur canvas asli diuji manual/E2E.
  **Acceptance:** test orkestrasi (fake decoder/encoder) lulus: urutan panggilan benar, opsi diteruskan, error decode menghasilkan `EncodeResponse` error yang jelas; EXIF otomatis hilang (sifat re-encode) didokumentasikan di JSDoc.
  **Dependencies:** Task 4. **Files:** src/encoders/canvasEncoder.ts, tests/canvasEncoder.test.ts. **Scope: S**

- [ ] **Task 6: core/protocol.ts — handler worker murni**
  `handleEncodeRequest(req: EncodeRequest, encoder: ImageEncoder): Promise<EncodeResponse>` — murni, encoder di-inject (SRP: worker.ts hanya jembatan pesan ⇄ handler). Test-first: sukses, error encoder, blob size/properti terisi, id request terkirim balik.
  **Acceptance:** test sukses + error path lulus; worker.ts tipis (<30 baris logika).
  **Dependencies:** Task 4, 5. **Files:** src/core/protocol.ts, src/worker.ts, tests/protocol.test.ts. **Scope: S**

## Yang sengaja tidak ada di v1 (KISS, bisa jadi fase lanjut)

ZIP batch download (JSZip), PWA/service worker offline, resize/crop, AVIF (encoder lambat), background removal. Semua bisa ditambah belakangan tanpa ubah arsitektur — cukup encoder/interface baru.

## Risks and Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| happy-dom/jsdom tidak punya encoder canvas asli | High | Sudah diantisipasi desain: logic murni di core/ diuji penuh di Node; jalur canvas diisolasi di balik `ImageEncoder` + dependensi injectable |
| WASM jSquash ribet di-bundle Vite (worker + asset) | Medium | Ditaruh fase terakhir, terpisah; CanvasEncoder tetap fallback; kalau gagal, MVP tetap utuh |
| ES module build tidak jalan via `file://` | Low | Dokumentasikan `npx serve dist`; `base: './'` |
| PNG via canvas besar hasilnya (24-bit tanpa optimasi) | Low | OxiPNG ada di Task 9; sementara dokumentasikan WebP sebagai rekomendasi default |
| Windows: perintah npm di Git Bash | Low | Gunakan `npm run ...` standar; sudah umum aman |
